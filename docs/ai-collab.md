# AI 协作协议：一次提需求，全程自动干活

这份文档解决一件事：**用户只在开场提一次需求，AI 全程自动推进，一次对话交付完整产品**。历史踩坑见 [lessons.md](lessons.md)；部署任务让 AI 先读 [deploy/ai-runbook.md](deploy/ai-runbook.md)。

## 核心模式

用户开场说清目标（一句话也行，带现象和验收标准更好），之后不再逐条指示。AI 负责：

1. **自己补全需求**：细节按默认决策清单、项目惯例、产品常识定，不反问。
2. **自己解决途中所有问题**：查现场、查文档、跑测试、修 bug，都自己来。
3. **主动加码**：主线跑通后，按更高标准补齐体验、文案、边界情况，汇报时列出加了什么。
4. **卡点不停等**：见下节。

## 卡点处理（不阻塞）

遇到无法自行解决的事——缺凭据、缺外部信息、需要用户环境、不可逆操作——**不停下来干等**：

- 记入「待你处理」清单：卡在哪、我建议的默认做法是什么；
- 先跳过，继续做其余能做的部分；
- 回复末尾集中列出清单；你下一句话补了输入，我就接着做。

## 默认决策清单（AI 自行决定，不问）

- 视觉细节（配色/间距/字号/动效）→ 按 [design-guide.md](design-guide.md)
- 文案 → 客服口吻说人话、给下一步动作，不出现实现词
- 实现方式与文件组织 → 按现有代码结构惯例，不顺手重构无关代码
- 提交信息 → 中文讲清改了什么、为什么；只提交相关文件
- 验证 → 后端跑测试（mock，不碰真实站点）；页面改动浏览器走查核对
- 动手前 → 先翻 [lessons.md](lessons.md) 和 Serena 记忆，不重踩

## 红线（即使全自动也不做，进待确认清单）

删数据、发版上线、重启用户在跑的服务、明显超出原需求的破坏性变更——一律不擅自执行，记入「待你处理」清单等用户点头。

## 需求模糊时

不反问。列出关键假设（给谁用、核心链路是什么），按假设直接做 v1；假设错了下一轮改，通常比等确认更快。

## 长任务纪律（借鉴 OpenHands 的自动化精华）

- **先计划后执行**：拿到需求先列任务清单，边做边更新；多模块大任务拆 subagent 并行，不等串行。
- **进度落盘**：每个阶段完成即把「目标 / 关键决策 / 当前进度 / 待处理」写进 `.zcode/plans/<任务名>.md`——会话被压缩或中断都能无损续跑；跨会话有价值的沉淀才进 docs/。
- **完成判据**：任务完成 = 自验绿（测试通过 / 页面走查），不是"我觉得写完了"；交付前再自查一轮：红线命令、漏验证项、文案口气。
- **防死循环**：同一问题连续两次用同一修法失败就换思路；再失败就记入「待你处理」清单跳过，不硬磕。
- **知识即触发**：[lessons.md](lessons.md) 顶部有触发词索引，写码途中命中关键词（401 / 代理 / 骨架屏 / Docker…）先翻对应坑再动手。

## 经验沉淀的闭环

每次踩新坑（现象 + 根因 + 方案）做完后：项目通用的追加进 [lessons.md](lessons.md) 对应分类，跨会话硬约束写入 Serena 记忆。经验库是活的，每个新会话自动带上。
