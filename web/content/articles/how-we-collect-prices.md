看价格表的时候，你可能想过一个问题：这些数靠谱吗？这篇就回答它。先说结论：价格不是人工抄的，也不是 AI 看一眼页面记下来的——每一轮采集，都是确定性代码先去站点取数、套公式算价，AI 只在格式认不出来时兜底，兜完还要过校验。下面讲这条流水线怎么转，以及反爬和短效凭证上踩过的坑。

一个响应进来，管线按它的类型分流，越靠前的路径越确定：

| 响应长什么样 | 走哪条路 | 谁来算价 |
| --- | --- | --- |
| JSON，new-api/one-api 倍率格式 | 本地公式，AI 只把俗称对成正式模型名 | 公式 |
| JSON，新版平台分桶格式 | 直接读站点标注价 | 公式 |
| JSON，其他格式 | 证据预筛后交给 AI，结果过三重校验 | AI |
| HTML 或纯文本 | 页面内嵌价格表 → 引用的 JS chunk → AI | 先公式，后 AI |
| 站点配了网页模式 | Playwright 渲染后，按 HTML 那行走 | 先公式，后 AI |

## 倍率站直接套公式

市面中转站大多用 [new-api](https://github.com/QuantumNous/new-api) 或它的前身 one-api 这类开源面板，价格接口返回的不是单价，是倍率。输入价 = 模型倍率 × 2 × 分组倍率，输出价同理；新版计价格式（`billing_denomination_version` 为 2）直接读站点标注的官方价。阶梯计费也完整解析：上下文分档、缓存读写价都保留成档位表，不压成一个均价。

这条链路里 AI 只干一件事：把俗称解析成正式模型名，比如把「GPT-5.6 Sol」对上 `gpt-5.6-sol`，解析完仍用公式重算；AI 失败就直接输出公式结果。不让 AI 碰数字的原因很直接：倍率本来就躺在站长后台随手可改（[上一篇](/articles/relay-station-traps)讲过这个坑），数字再经 AI 转述一遍，今天读成 3.0 明天读成 8.0，你分不清是站点调价还是抽取出错。

## AI 只做兜底

非倍率格式的接口和页面才交给 AI。调用本身就有约束：每站每轮最多一次，证据先按目标模型预筛、截断长度，不把整个响应原样丢过去；同样的证据走缓存，不重复调用。

缓存上踩过一个不报错的坑。new-api 系接口每次请求会把模型数组重新洗牌，还往随机模型上挂随机哈希字段——两次响应字节数相同、顺序不同，直接算哈希，缓存每轮全部失效，等于每轮全额重跑。现在的缓存键先做顺序规范化：按内容排序、整数值浮点归一、剔掉已知的噪声字段，再进哈希。

抽出来的结果要过三重校验：模型名必须字面出现在证据里，防止把证据里没有的价格安到这个模型头上；「已确认」要求网络证据和价格数值同时闭环；只有计费规则的必须带真实规则。过不了就降级，如实标拿不到，不猜。

分批按预算走。一条完整价格记录约 300 到 700 token，按每条 1200 token 留余量折算批大小，输出预算 16000 token 时 12 条一批。批太大，输出会在中途截断成非法 JSON；批太小，重复的系统提示和调用次数翻倍。批与批并行跑，总时长预算随批次数等比放大，40 个模型的全量提取正常要 10 分钟起步，固定上限必然贴线爆炸。

## 反爬：先读响应体

挂着 Cloudflare 盾的站点，WAF 拦的是缺 Referer 的请求，不是程序指纹——httpx 和 curl 的 TLS 指纹一样能过；请求头补上同站 Referer、Origin 和 Accept，匿名请求也能拿到 200。有一回 403 的报错文案提示「可能需要认证」，翻响应体里的 new-api message 才发现根本不是登录的事。

new-api 系的认证接口还有个特殊要求：光带 Cookie 不够，必须再带 `New-Api-User` 头，值是登录用户 ID，缺了直接 401。这些细节文档里不一定写，但响应体里的 message 会说实话。

> 排障时别看状态码猜，读站点返回的原文。

## 短效凭证自动续签

采集的站点不少要登录，而 new-api 的会话设计得很紧（源码 `service/auth_token.go`）：Access Token 只有 15 分钟有效；每个登录会话自创建起最长 30 天，续签不延长；refresh token 一次一换，旧值在 30 秒宽限窗口外再被使用，防盗机制直接注销整个会话。

所以续签是自动的：请求被 401 拒了，先拿 refresh token 换新的，新值从响应的 `Set-Cookie` 里接力，再用新 token 重试一次。凭证注入统一收口，价格、渠道状态、公告三类请求共用一套规则，认证头不在各接口里手写——写死会盖掉注入的凭证，token 换新追不上。

## 网页响应：内嵌表、打包 JS、真浏览器

抓到 HTML 而不是 JSON 时，解析分三步。先找页面内嵌的结构化价格表，找到目标模型就确定性计价，AI 不参与；页面里没有，再顺着页面引用翻打包 JS——chunk 最多追 15 个，文件名带内容哈希，每次采集重新发现引用，站点改版也能跟上，价格常常整包躺在里面。有个站实测下来，登录墙后的页面价格全在前端打包 JS 里，根本不用登录——先确认数据在哪，再谈登录态。两步都空手而归，才把页面文本交给 AI 抽取；chunk 里能看到模型名但格式认不出时，AI 看的也是那份 chunk，不是空壳 HTML。

真要跑 JS 才出价格的站，得在配置里显式切到网页模式，用 [Playwright](https://playwright.dev) 无头浏览器渲染：注入 cookies 和 localStorage 登录态，等页面跑完（默认 3 秒），拿渲染后的 HTML 再走上面同样的三步。这里没有自动回退——直采抓到空壳就按失败上报，要浏览器的站由管理员明确选择。

## 官方价从哪来

折扣率要有个分母：官方列表价。目录数据来自 [models.dev](https://models.dev)，一个开源模型价格目录，走 Cloudflare CDN 分发，不要密钥，同步秒级完成。但它的国内价格一律不收——时段分档缺失，还是他方汇率换算价，实测与官方人民币标价偏差不小。国内厂商的基准价只来自厂商自己的定价页：确定性解析优先，Markdown 表格、HTML 表格、内嵌 JSON 挨个试，AI 兜底防幻觉。

官方目录还有一道品牌闸门：按模型名判归属，定价页上托管、转售他家的模型——云厂商挂出的 DeepSeek、聚合平台代销的开源模型——不进官方目录。OpenAI 的折扣，不能拿别家的转售价当基准。

汇率多源容灾：ExchangeRate-API 的免费端点、CDN 分发的 currency-api、欧央行数据的 Frankfurter 挨个探测，全挂了回退本地缓存。全表锁定同步时点的快照汇率，页面展示和折扣计算用同一个数。

## 别把没变的价报成变了

价格变化事件的判定指纹只含价格口径字段：单价、缓存价、计费规则数值、币种、状态、认证。AI 抽取每轮会漂移的上下文边界、备注文本一律不参与，不然价格没动，「降价了」的事件先响了。其余的工程兜底：每站硬超时，卡死不拖垮整轮；单站采完立即落库；境内采不到境外站时直连优先、失败走代理、恢复切回。

这些机制落到页面上，是你能看见的东西：

- 每条价格的证据都有存档：来源地址、状态码、内容哈希，认证头自动脱敏。
- 「正常 / 规则价 / 待确认 / 需认证」的状态如实标注，拿不到可靠价格就显示拿不到。
- 价格变化事件不是 AI 说了算，指纹只看价格口径字段。
- 折扣率用快照汇率统一折算，展示与计算一个口径。

这些都在后台跑，平时看不见，出问题时才显出来：能查到是哪一环出了错，价格变了能确认是站点真变了。
